## Formal Review Sign-Off

### 1. Security Reviewer
* **Verdict**: APPROVED
* **Evaluation**:
  * **Credential Isolation**: Client configuration uses `NEXT_PUBLIC_` prefixes while server dispatch credentials (`FIREBASE_SERVER_KEY`) are kept strictly server-side with an explicit browser throw-guard.
  * **Zero IDOR on Token Registration**: `saveDeviceTokenAction` in `lib/push/actions.ts` binds `fcm_device_token` strictly to `auth.uid() = user_id`.
  * **Service Worker Origin**: Scoped strictly to the root origin `/` without insecure external script injection.

### 2. Code Reviewer
* **Verdict**: APPROVED
* **Evaluation**:
  * **Standards Compliance**: Service worker follows W3C Service Worker specifications with `skipWaiting()` and `clients.claim()`.
  * **TypeScript Strict Mode**: Zero `any` in `lib/push/firebase-config.ts` and `lib/push/client-token.ts`.
  * **Graceful Degradation**: Fallback raw push event listener handles payloads even if Firebase SDK wrapper is bypassed.

### 3. Performance Reviewer
* **Verdict**: APPROVED
* **Evaluation**:
  * **Client Match Reuse**: `clients.matchAll({ type: 'window' })` navigates existing open application tabs instead of spawning redundant browser processes.
  * **Optimized Partial Indexing**: Database migration introduces a partial index `WHERE fcm_device_token IS NOT NULL` to avoid indexing unsubscribed candidates.
