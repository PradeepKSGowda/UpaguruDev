## Objective
Implement the public REST API endpoint `GET /api/v1/notifications` in Next.js 15 App Router. The route handler enforces Upstash Redis sliding window rate limiting (60 req/min per IP), validates all query parameters (`limit`, `offset`, `category`, `state`, `sort`, `search`) via Zod, returns RFC 7807 compliant Problem Details error responses on invalid parameters, queries published exam notifications from Supabase PostgreSQL with exact counts and related exam data, and responds with Edge caching headers (`s-maxage=300, stale-while-revalidate=600`). In addition, provide the database audit schema with mandatory RLS in `public-api-schema-v1.sql`.

### 1. Code Reviewer
* **Verdict**: APPROVED
* **Evaluation**:
  * **Input Validation & Types**: Strict Zod schema coercing numeric fields with boundaries (`limit` 1-100, `offset` >= 0) and enum constraints preventing SQL/PostgREST injection.
  * **RFC 7807 Compliance**: Both validation errors and runtime failures return `application/problem+json` matching industry standard API error contracts.
  * **Clean Architecture**: Clean separation between schema validation (`lib/schemas/api.ts`) and route execution (`app/api/v1/notifications/route.ts`).

### 2. Security Reviewer
* **Verdict**: APPROVED
* **Evaluation**:
  * **Rate Limiting Guard**: In-flight requests are throttled at the ingress point via Redis sliding window before database execution.
  * **Data Segregation**: Anonymous public consumers can only view notifications where `status = 'published'`. No draft, archived, or internal fields are exposed.
  * **Mandatory RLS**: Audit logging table `api_request_logs` enforces RLS with idempotent policies restricting access to platform admins and service roles.
