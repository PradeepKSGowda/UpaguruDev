## Objective
Build two public REST API v1 route handlers in Next.js 15 App Router:
1. `GET /api/v1/exams`: Enumerate canonical competitive exam entities with category, jurisdiction, search filtering, and linked active notification counts.
2. `GET /api/v1/search`: Provide high-performance full-text search across published exam notifications leveraging PostgreSQL GIN indexes, textSearch websearch queries, and graceful ILIKE fallback.

Both endpoints enforce sliding window rate limiting (60 req/min per IP), validate query parameters with Zod, emit standard RFC 7807 Problem Details on invalid inputs, and configure appropriate Edge CDN cache headers (`s-maxage=600` for exams, `s-maxage=60` for search).

## Formal Review Sign-Off

### 1. Code Reviewer
* **Verdict**: APPROVED
* **Evaluation**:
  * **Strict Typing & Contracts**: Clean domain interfaces (`ApiExamItem`, `ApiExamsResponse`, `ApiSearchResponse`) preventing arbitrary leaks of unneeded columns.
  * **Search Resilience**: Multi-tiered search approach utilizing GIN `.textSearch()` with graceful fallback to sanitized multi-column ILIKE matching ensures zero query failures.
  * **Consistent RFC 7807 Errors**: Both handlers share the unified `formatRfc7807ValidationError` helper, guaranteeing predictable error payloads for consumer SDKs.

### 2. Security Reviewer
* **Verdict**: APPROVED
* **Evaluation**:
  * **Query Parameter Sanitization**: All incoming free-text parameters are trimmed and sanitized against SQL wildcard characters (`%` and `_`) to eliminate search enumeration exploits.
  * **Public Data Boundaries**: Search is strictly restricted to `status = 'published'` notifications. Internal drafts, rejected extractions, and archived notifications are completely unsearchable.
  * **Mandatory RLS**: Telemetry table `api_search_telemetry` strictly enforces RLS, preventing unauthorized reads while allowing service-role ingestion.
